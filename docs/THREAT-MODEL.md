# Threat model (RMM platform)

Scope: controller API + dashboard, Windows Worker, the link between them, the local AI. Labels: **MITIGATED** (control exists and is tested), **PARTIAL**, **OPEN**.

| # | Threat | Control | Status |
|---|---|---|---|
| 1 | A technician of client A reads/acts on client B (IDOR, route guessing) | Single server-side choke point `tenancy.authorize`: default-deny; resources resolve to an organization; same 403 for "forbidden" and "does not exist"; denials audited. Groups, jobs, scripts, AI runs, inventory all carry the org and are checked again in handlers. Tests: `test_tenancy`, `test_rbac`, `test_ops`, `test_ai`, `test_monitor`, `test_billing` | MITIGATED (API). Live check on the real Worker: another client's token got 403 on 5/5 probes |
| 2 | Privilege escalation (technician approves own change, admin makes admins, owner role minted) | Roles fixed server-side; owner exists only as the built-in token; four-eyes approval for modifying jobs and schedules; disruptive jobs need a typed phrase and cannot be scheduled; administrators cannot create administrators or reach other clients | MITIGATED |
| 3 | Stolen technician token | Hash-only storage, shown once, rotation and instant revocation, offboarding revokes, per-minute failed-auth limiter (429), token kept per browser tab (not persisted), HTTPS via the reverse proxy | PARTIAL: no expiry/MFA/SSO yet; a stolen live token works until revoked |
| 4 | Stolen owner token (`CIT_API_TOKEN`) | Prefer `CIT_API_TOKEN_FILE`; production refuses tokens shorter than 32 characters. The owner token can only be replaced by restarting with a new one | PARTIAL |
| 5 | Man-in-the-middle between controller and Worker | Pinned TLS fingerprint compared by a human at enrollment; per-Worker revocable credential; a different certificate on the same address is refused | MITIGATED on LAN (real PCs). Internet path **not tested** |
| 6 | Worker control port exposed to the Internet | Controller refuses public addresses (`netpolicy`); design requires an overlay VPN (Tailscale/WireGuard) | PARTIAL: enforced in the controller; the Worker's own bind address and firewall are an operator duty |
| 7 | Command injection through templates | Template parameters are regex-validated; argv-only execution; the only free-form text is the shell+body an operator submitted and a second person approved; the AI never produces commands | MITIGATED (tests include injection strings) |
| 8 | Prompt injection through machine output into the AI | Output sanitized, truncated and fenced as untrusted data; the model may only choose from a read-only allowlist and write prose; command-like sentences are stripped; fixes only via proposals needing human approval; tested with hostile service names and a disallowed-tool reply; real small model observed to emit a command sentence once and the filter removes it | MITIGATED for this design; a model can still write misleading prose (labelled as AI output next to the raw evidence) |
| 9 | Destructive operation by mistake | Risk classes, approval, preview, audit; reboot/shutdown typed confirmation; restore points are **guidance only** (no automatic restore point yet) | PARTIAL |
| 10 | Audit tampering | SHA-256 hash chain verified in `/status`, `/ready` and backups; **unkeyed**: someone with database write access can recompute it | PARTIAL (detects accidents, not a determined local administrator). Ship logs off the box for stronger evidence |
| 11 | Secrets in logs/DB | Tokens and invitations stored as hashes; licenses HMAC-signed; request bodies never logged; Worker secrets in DPAPI; the license signing key is DPAPI-protected on Windows (0600 file elsewhere); JSON logs carry no bodies | MITIGATED (tests assert tokens are absent from DB and audit) |
| 12 | Denial of service / brute force | Auth-failure limiter; job output capped (64 KB/run); bounded retention for samples/alerts; job pool of 8 | PARTIAL: no global request rate limit; add limits at the reverse proxy |
| 13 | CSRF | API uses `Authorization: Bearer` headers only (no cookies), so browsers never attach credentials automatically; strict CSP and same-origin API in the Caddy config | MITIGATED by design |
| 14 | Data of an offboarded client lingers | Offboard revokes people and Worker credentials, retention window, owner-only purge with typed name; the audit chain is kept by design | MITIGATED (Workers that were offline must also run `cit-worker revoke-all`) |
| 15 | Malicious customer machine attacks the controller | Worker output is data (capped, never executed); controller talks to Workers over pinned TLS only | PARTIAL: a Worker runs all its clients as one Windows user; use separate Workers for hostile clients |
| 16 | Supply chain (unsigned binaries, updates) | Binaries are local builds, hash-checked on copy; **no signing certificate, no auto-update** | OPEN |

Residual risks to accept knowingly: no MFA/SSO, no token expiry, unkeyed audit chain, unsigned Worker binaries, Internet path unproven.
